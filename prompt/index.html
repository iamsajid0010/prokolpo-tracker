Full prompt (verbatim)

ROLE: You are a senior full-stack AI product engineer. Build and deploy, in ONE run with no further guidance, a complete, public, enterprise-grade web product. Work autonomously; only ask for simple approvals.

PRODUCT: "Prokolpo Tracker" (প্রকল্প ট্র্যাকার). Domain: CivicSphere AI, challenge "Transparent Government". Citizens, journalists and auditors in Bangladesh drill down Division > District > Upazila > Union, see government projects, progress, budget vs disbursement, material price audits against benchmark rates, a next-day progress projection, a Bangla/English copilot, and can anonymously report problems.

HONESTY RULES (highest priority; the competition forbids fabricated or simulated results):
- Every page shows a banner: "Synthetic demo data. Not real government records." (Bangla too).
- Every feature carries a visible tag: "Implemented" (really works in the browser), or "Planned" (not built). Never present a Planned item as working. Do NOT claim OIDC, 2FA, AES-256, pgvector, MCP agents, scrapers, Dhaka-region hosting, IMED routing or any certification unless really implemented. Describe the real stack truthfully.
- No hash-based fake numbers for AI outputs. The "next-day projection" must be a real computation (linear regression over each project's 14 daily progress records stored in the seed data), labelled "statistical projection", with the formula and inputs shown. Weather adjustment must use the real Open-Meteo API (no key; Dhaka lat 23.8, lon 90.4; fall back gracefully offline with a clear "offline, weather not applied" note).
- The copilot is a transparent keyword-and-passage retrieval over a local knowledge base (BoQ data, benchmark rates, procurement guidance). Label it "retrieval copilot (rule-based)". Every answer cites its passage. Legal/rate figures are tagged "illustrative, verify with official source". Do not state specific rule numbers or penalty percentages as fact.
- Use only fictional company names (e.g., "Demo Steel Co.", "Demo Cement Ltd.", "Demo Builders Ltd."). Use neutral language: "Review recommended", "Above benchmark", never "corrupt" or "critical overpricing detected". State that benchmarks ignore transport and bulk discounts, so flags are advisory and a human decides.
- Never use external CDNs or Google Fonts; use system fonts with a Bangla-capable fallback stack (Noto Sans Bengali, Kalpurush, system-ui), so the privacy/sovereignty claims are true.

TECH: Static multi-page site, no backend required: vanilla HTML/CSS/JS (ES modules), one shared CSS and JS core, seed data in JSON files. Real path routes with one folder + index.html per route (not hash routing), so each URL works directly and without JavaScript still shows meaningful server-rendered text content (headings, descriptions, and key tables pre-rendered in HTML). State (votes, flags, approvals, reports, language, theme, lite mode) persists in localStorage with try/catch. Deploy to a public host (Vercel via CLI, else GitHub Pages or Netlify) and print the final public URLs. No login anywhere.

ROUTES (all public, all bilingual EN/বাংলা toggle with Bangla digits and কোটি/লাখ currency formatting in Bangla, responsive, dark mode, accessible, keyboard-navigable, reduced-motion safe):
1. /app: Main app. Cascading Division/District/Upazila/Union selectors with Bangla names, quick-jump chips, summary cards, project cards, project detail tabs (Overview, Price audit, Daily log). Seed at least 8 divisions, 2 districts each, with at least 3 unions fully hand-authored with 3-4 projects each (Ashulia and Birulia in Savar, Dhaka must be included); the rest may be marked "no data yet" honestly instead of generated filler. Verify Bangla names are correct; mark any uncertain union name list as "demo list, verify with official LGD data".
   Per project: ID, agency, contractor (fictional), budget, disbursed, start, deadline, progress, 14 daily progress records, materials with qty and billed unit price, daily logs.
   Must-have logic: (a) deadline status computed from the REAL current date (new Date()), not hardcoded; (b) price anomaly: >5% amber, >15% red, estimated excess = only sum of items above 5%, and the banner must exactly match row badges; (c) RED FLAG "Disbursement ahead of progress" when disbursed% minus progress% > 15 points, and "Past deadline with disbursement over 70%"; disbursement can never exceed 100% of budget; (d) contractor track record and repeat-delay indicator; (e) confirm/flag buttons limited to one action per log per browser (toggle), anonymous; (f) real Web Speech API voice input (bn-BD and en-US) with graceful fallback message if unsupported; (g) knowledge graph (inline SVG) Ministry > Agency > Project > Contractor > Suppliers > Union, nodes clickable with a details panel; (h) role views Citizen / Journalist / Union Overseer that genuinely change visible panels; (i) lite mode that truly avoids loading charts/SVG and images and shows tables only.
   Do not leak admin state into /app; roles are explicit UI modes only.
2. /demo-user: one click, no form, opens a ready citizen session (persona: "Demo Citizen", Ashulia Union) with nearby alerts, the anonymous report form (stores a locally generated random report ID with crypto.randomUUID, shows status "Saved locally in demo; not transmitted"), and links into /app.
3. /demo-admin: one click, opens an auditor session with the log approval queue, anomaly escalation list, counters that update live, and a "Run audit scan" button that really recomputes anomalies and disbursement red flags across all seed projects and lists the findings.
4. /admin: user list with role dropdowns, contractor watchlist (not "blacklist"; with note that humans decide), editable benchmark rates (validate positive numbers, all materials editable, changing a rate really recomputes badges everywhere), AI-feature toggles that really enable or disable the projection and copilot. Tag as demo with no real authentication ("Planned: SSO and 2FA").
5. /data: truthful data architecture: list real data sources used (seed JSON files, Open-Meteo API), list planned sources (IMED, e-GP, PWD schedule) tagged Planned, schema/ER diagram in SVG, a data-flow diagram in SVG (seed JSON > browser > rules engine/projection > UI), lineage example for one badge, data dictionary table, and download buttons for the seed JSON.
6. /security: truthful controls. Implemented: no login, no cookies, no third-party trackers, no external fonts/CDNs, localStorage-only data, HTML escaping everywhere (escape quotes too; no inline handlers with user data), strict Content-Security-Policy meta tag, anonymous reports with no IP stored by this static site. Planned (clearly tagged): SSO, 2FA, encryption at rest, Bangladesh-region hosting, formal audits. Include data-sovereignty and responsible-AI sections (human in the loop, advisory flags, sources shown, bias note, limitations).
7. /architecture: the 8-layer reference architecture (User Interaction, Application Logic, AI Intelligence, Knowledge Retrieval, Agent Orchestration, Data Infrastructure, Automation, Deployment) as a real SVG system diagram showing Implemented vs Planned for each layer, plus interactive layer details and a request-flow walkthrough.
8. /presentation: 5-section product story with a working 3:00 timer, Problem > Solution > Walkthrough > AI approach > Impact; KPIs labelled "targets, not achieved results".
9. /pitchdeck: 10-slide YC-style deck (Problem, Solution, Market, Product, Traction, Business model, Growth, Team, Impact, Ask) with keyboard arrows, fullscreen, and print-to-PDF CSS. Market: show sourced-style estimates clearly marked "to be validated". Traction: honestly "working prototype, no users yet". Team: solo builder (individual competition) with optional advisors "Planned". Ask: a concrete, modest ask with amounts marked illustrative.
10. /audit: a one-click audit that runs REAL automated checks in the browser and shows pass/fail with evidence: all 10 routes reachable (fetch each), no external network requests (inspect resource timing), CSP present, localStorage works, anomaly banner equals sum of row flags, disbursement never above budget, deadline logic uses current date, Bangla toggle changes all headings, lite mode removes SVG, benchmark-rate edit recomputes badges, weather API reachable or fallback active, Implemented/Planned tag coverage. Show score = passed/total (no hardcoded scores), timestamp, copy-report and download-JSON buttons, plus residual risks and limitations.
11. /prompt: shows THIS ENTIRE PROMPT verbatim in a copyable block, the tool name "Claude Code", the tool URL https://claude.com/product/claude-code, the reason for choosing it, the challenge selected, and links to every route and to documentation.
12. /docs: README-style documentation: purpose, how to test in 2 minutes (click demo-user, demo-admin), feature list with Implemented/Planned status, data sources, limitations, ethics.

NAVIGATION and UX: persistent sidebar with all routes; a "Start here / 2-minute walkthrough" onboarding card on /app with sample data prefilled and tooltips; empty, error and loading states; every page has a title, meta description, lang attribute, skip link, focus styles, WCAG AA contrast; mobile first.

QUALITY GATES before you finish (run and fix yourself, no user input): serve locally and fetch every route (HTTP 200, no console errors); test Bangla toggle and lite mode on each route; validate JSON; run the /audit logic in a headless check if possible; fix all failures; then deploy and print public URLs for /app, /demo-user, /demo-admin, /admin, /data, /security, /architecture, /presentation, /pitchdeck, /audit, /prompt, /docs. Finish with a short summary listing anything you could not implement, honestly marked Planned.

Begin now and complete everything without asking questions.
